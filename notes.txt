1. PROBLEM AND GOAL
-----------------------------------------------------------------------------
A robot must find a target object in a building. It only has a structured
description of the building derived from an IFC model (rooms, their function,
the equipment inside, doors/connectivity). A VLM/LLM reasons about WHERE the
object is likely to be, a route over the likely rooms is planned, and at each
stop a camera image is checked by a vision model.

Pipeline (current):
  0. Task interpretation  - classify input: find_object / go_to_room /
                            building_query / none (local LLM via Ollama)
  1. Semantic ranking     - LLM gives raw 0-1 score per room -> softmax -> p(room)
  2. Route planning       - take rooms until prob_mass covered, order the visit
                            (Held-Karp optimal for small N, greedy NN fallback)
  3. Visual confirmation  - image at each stop sent to a vision model

3. DESIGN DECISIONS: WHAT WAS CHOSEN AND WHY NOT THE ALTERNATIVES
-----------------------------------------------------------------------------

3.1 Own IFC cleaning script (clean_ifc.py) vs. generic IFC->JSON converter
    Candidate rejected: buildingSMART ifcJSON converter
    (https://github.com/buildingsmart-community/ifcJSON), added to the repo as
    file_converters/ in commit 072ebd3 (2026-09-30).
    Findings [FACT, user's tests]:
      - With IfcOpenShell 0.8.5 the converter crashed on import.
      - After patching it, it shortened every GUID. On the IDAC model all 15
        rooms collapsed onto 2 IDs, so it is impossible to tell which furniture
        belongs to which room -> breaks the room->equipment mapping that the
        whole pipeline depends on.
      - Repo's last listed update: April 2024 (stale w.r.t. current
        IfcOpenShell).
    Defence of own script:
      - Uses the current IfcOpenShell API directly.
      - Keeps only what the task needs: spatial hierarchy, every IfcSpace
        (name/function/area/centroid), equipment (IfcFurniture /
        IfcBuildingElementProxy) with its containing room, doors with the rooms
        they connect. Output is small enough to fit in the LLM context.
      - A generic converter is lossless but huge (geometry, property sets) and
        not room-centric; the LLM would need further filtering anyway.
    Status: converter kept in file_converters/ as a reference/baseline, not part
    of the active pipeline.

3.1b clean_ifc.py v2: generic extractor instead of a keep-list (2026-10-09)
    What: keep-list (IfcSpace/IfcFurniture/IfcBuildingElementProxy/IfcDoor)
    replaced by "every rooted entity except a blacklist" (IfcAnnotation,
    IfcGrid, IfcStructuralItem/Activity/AnalysisModel). Output split into
    <name>_full.json (everything) and <name>_llm.json (rooms, equipment,
    adjacency). Records keyed by GlobalId; names are display only.
    Why:
      - A keep-list silently loses anything the exporter modelled with another
        class (IfcFlowTerminal sinks/lights, IfcFurnishingElement in IFC2X3).
        A blacklist fails open and is schema-agnostic (tested IFC2X3/4/4X3).
      - Name-keyed v1 output cannot handle duplicate or numeric room names
        (Revit: Name "101", LongName "Office"). Same failure class as the
        ifcJSON GUID collapse in 3.1.
      - Units: v1 assumed metres. v2 converts every length/area/volume/angle
        (direct attributes via the schema's declared measure type, psets/qtos
        via their measure type or own Unit). Verified: synthetic_office
        converted to mm gives identical output.
      - Door connectivity: v1 used only IfcRelSpaceBoundary, which many
        exports lack (ac20 has 0 boundaries). v2 adds a geometric fallback
        (probe 0.5 m either side of the door along its local Y axis,
        point-in-polygon against space footprints) and records the source.
      - Equipment-to-room: relation first (containment, spatial reference,
        aggregation parent chain), then centroid point-in-polygon; recorded
        as room_source = relation | geometric.
      - Pset dropping: substring keywords ("material", "energy", ...) replaced
        by exact names (DROP_PSET_EXACT, initially empty, extend with
        --drop-pset). Substrings can hit useful psets; the audit lists every
        pset name seen, so the drop list is chosen from evidence.
      - Silent `except: pass` removed: every caught exception is counted by
        stage | class | error type in the audit (semantic-quality variable).
      - Geometry: one multi-threaded ifcopenshell.geom.iterator pass instead
        of create_shape per entity; footprint = union of projected triangles
        (shapely), centroid = footprint centroid (v1 used the vertex mean,
        biased for L-shaped rooms).
    Alternatives considered:
      - Keep v1 and add classes to the keep-list: does not generalise to
        unseen exporters.
      - Export resource entities as records (like ifcJSON): huge and not
        object-centric; resources are folded into the object that uses them.
      - Separate script for the LLM view: kept in one file behind
        --no-llm-view so both views come from the same run.
    Deviations from the written plan (decided while implementing):
      - ObjectPlacement, RepresentationMaps, HasPropertySets also dropped from
        the attribute dump (represented by geometry / psets instead).
      - IfcSlab excluded from obstacles (it is the floor); only slab openings
        are added, as floor-level hazards.
      - When IfcRelSpaceBoundary links a door to >2 spaces (Duplex_A), the
        geometric probe picks the two spaces actually either side of it.
      - Models without IfcBuildingStorey (IDAC_Model: spaces directly under
        IfcSite) get one whole-model obstacle/grid layer; audit.no_storeys.

3.1c Split into the ifc_extract package + make_grid.py (2026-10-09, v2.1)
    What: clean_ifc.py (1,543 lines, IfcExtractor alone ~460 lines mixing
    routing, rooms, doors, obstacles and frame) split into
    scripts/ifc_cleaning/ifc_extract/{common, audit, units, relations,
    geometry, exporter, rooms_doors, obstacles, extractor}.py; clean_ifc.py is
    a 71-line CLI. Occupancy grids moved to make_grid.py, which reads
    <name>_full.json (removes the private _shape/_id keys that existed only for
    the grid). Largest module: exporter.py, 344 lines.
    Why: debuggable units with one responsibility each, describable in the
    thesis as a pipeline; grid generation decoupled from IFC parsing (it can be
    rerun at another resolution without re-reading the IFC).
    Verified: on all 5 real models the refactor gives identical rooms,
    equipment, adjacency and door links; footprint centroids move <= 1 mm.
    Fixes made at the same time (from review of v2.0 with a mm IFC4 fixture):
      - Grid: unknown cells written as 128, not 205. nav2 map_server reads
        (255-p)/255; 205 -> 0.196 <= free_thresh 0.25 -> everything outside
        the building loaded as FREE. 128 -> 0.50 -> unknown.
      - Project/Site/Building now in a "spatial" bucket, not "elements".
      - Obstacles: elements below the lowest storey, with an unmatched storey,
        below the floor or without a footprint are counted in
        audit.obstacles_skipped (were silently skipped).
      - Virtual boundaries without an element: pair keyed by the smaller
        boundary GUID (pairing made symmetric), so one opening = one edge
        (was 2). audit.virtual_boundaries_without_edge counts the rest
        (Duplex_A: 28, fantasy1: 8; previously invisible).
      - Door probe offset = max(door depth, host-wall layer thickness)/2 +
        0.3 m (was fixed 0.5 m, which landed inside walls > ~1 m). Fixture
        with a 1.5 m wall: offset 1.05 m, door linked correctly.
      - Grid size limit (--max-cells, default 50M/storey) with an error that
        names far-away obstacles (e.g. survey-point proxy); warning even under
        the limit. Rasterised in row blocks to bound memory.
      - IfcSite and openings that do not void a slab are no longer tessellated
        (audit.tessellation_skipped); they keep placement-based fields.
      - Found while splitting: footprints rounded to mm in the JSON could
        become invalid and crash make_grid (IDAC, ac20). Footprints are now
        snapped to the 1 mm grid when built, so rounding is a no-op.

3.3 Softmax over LLM scores instead of using raw scores / a fixed threshold
    Raw scores are not a probability distribution and do not respect "rooms
    already ruled out". Softmax gives p_i = exp(s_i/T)/sum_j exp(s_j/T) that
    sums to 1; ruled-out rooms are removed BEFORE the softmax so their mass is
    redistributed. Alternative (fixed score threshold, earlier --threshold
    flag) does not scale with building size; it is kept only as an alias of
    --min_prob. [RATIONALE: README/code]

3.4 Cover prob_mass (0.9) instead of fixed top-k
    Scales with the building: a sharp distribution -> 1-2 rooms, a flat one ->
    many. Fixed k would over-visit when the model is confident and under-visit
    when it is not. min_prob 0.01 drops negligible rooms.

3.5 Route ordering: Held-Karp (optimal) for few rooms, greedy nearest-neighbour
    otherwise. Held-Karp is exact but O(n^2 2^n), so greedy is the fallback for
    larger buildings. Start room falls back to the first room in the JSON when
    not given / not found (real models do not have a room called "Reception").

3.6 Task-interpretation stage (stage 0) added before ranking (commit 7fe44dc)
    Without it every input (greetings, questions, "go to X") would be scored as
    a search task. It classifies intent, uses the last few exchanges as
    context (so "go there" resolves), restricts to a named room, and
    short-circuits to rooms where the building model already records the
    target (e.g. a printer model number = printer). Ambiguous room references
    are refused with the room list rather than guessed.
    test_interpreter.py was added to batch-check phrasings without walking.
